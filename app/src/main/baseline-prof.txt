# BASELINE PROFILE
#
# On a fresh install, ART has no idea which code matters, so the first launches run
# interpreted/JIT — which is exactly why a Compose app feels sluggish for its first few sessions and
# fine afterwards. This file names the classes and methods on the launch and interaction paths so
# they are AOT-compiled at install time instead, typically cutting cold start substantially and
# removing the first-scroll jank.
#
# Line format: [flags]ClassDescriptor->method(params)ret
#   H = hot (called often)   S = startup (runs during app launch)   P = post-startup
# `**` wildcards match packages/methods. Rules that match nothing are ignored, so this stays valid
# as the code moves.
#
# HOW TO REGENERATE FROM REAL USAGE (better than these hand-written rules):
#   1. add a :baselineprofile Gradle module (androidx.baselineprofile plugin)
#   2. write a MacrobenchmarkRule journey: launch → Home → open a session → log a set → scroll
#   3. `./gradlew :baselineprofile:generateBaselineProfile` on a rooted emulator/userdebug device
#   4. drop the generated profile in over this file
# The plugin measures what actually runs; the rules below are the informed approximation.
# ─────────────────────────────────────────────────────────────────────────────
